# 《人机验证》部署说明（组织者用，不要发给选手）

## 一句话

单个 Python 3.12 标准库服务端 + 一个打包后的单页前端；选手只能看到网页源码，而源码里没有任何本局答案。

## 构建与运行

```bash
# 方式一：docker compose（推荐，平台注入 FLAG）
FLAG='SACC{真实凭据}' docker compose up -d --build

# 方式二：docker
docker build -t sacc-humancheck:deploy .
docker run -d --name sacc-humancheck \
  --read-only --cap-drop ALL --security-opt no-new-privileges:true \
  -e FLAG='SACC{真实凭据}' -e HOST=0.0.0.0 -e PORT=8080 -e TTL_SECONDS=7200 \
  -p 8080:8080 sacc-humancheck:deploy

# 本地跑（不用 docker）
FLAG='SACC{local-test}' PORT=8090 python -B app/server.py
```

要求：容器基础镜像 `python:3.12-slim`；非 root（UID/GID 10001）；只读根文件系统；无第三方依赖；不访问外网。

## 环境变量

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `FLAG` | 是 | — | 平台注入，必须匹配 `^SACC\{[^{}\r\n]{1,240}\}$`，否则服务拒绝启动（exit 2） |
| `HOST` | 否 | `0.0.0.0` | 监听地址 |
| `PORT` | 否 | `8080` | 容器端口（平台映射容器内 8080） |
| `TTL_SECONDS` | 否 | `7200` | 实例寿命，到点进程自行退出 |
| `RATE_MAX` | 否 | `40` | 每个 IP 60 秒内请求上限 |

## 谜底在哪里

**每一局都是随机的，静态代码里没有答案。** `/api/session` 建会话时服务端生成：

- 第 2 步验证码：5 位随机串（不含易混字符）
- 第 3 步隐藏身份：`h_` + 8 位随机 hex，只出现在运行时 DOM 的隐藏 option 上
- 第 5 步崩溃错误码：随机 `0x........`

前端只负责渲染，`/api/progress` 会同时校验「顺序」和「答案」，两者不符都是 409；五步齐了 `/api/claim` 才返回 FLAG。
所以就算有人把 base64 解开、把整段前端逻辑读明白，也只是拿到一份「攻略」，仍然要按六步真实通关。

## 给选手的访问方式

选手只通过 HTTP 访问实例；**不要**把 `deploy/` 目录、`app/server.py`、可读的源 `index.html` 或本说明发给选手。
`app/public/index.html` 是唯一对外页面：里面只有 header、空的 `<main id="app">`、footer 和一段 base64 loader。

## 验收（组织者自测）

```bash
CHALLENGE_URL=http://127.0.0.1:8080/ python -B tools/verify.py
python -B tools/audit_bypass.py
```

期望输出：`VERIFY_OK` 与 `AUDIT_OK`。

## 注意

- base64 只是让页面源码「不好读」，**不是加密**；本题的安全性依赖「答案在服务端」而不是「前端不可读」。
- 如果平台要求「选手完全看不到前端逻辑」，请把页面放进 iframe 之外再顺手做服务端渲染也不是本题目标；本题的目标是**读源码也拿不到答案**。
- 修改前端的流程：改项目根的 `index.html` → `python -B tools/build.py` 重新生成 `app/public/index.html` → 重启服务（服务启动时把页面读进内存）。
- 一个实例一个 FLAG；重启容器会清空所有会话（选手需刷新重来），FLAG 不变。
