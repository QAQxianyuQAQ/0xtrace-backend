# 题目浏览器入口 —— 交付说明（2026-11-04）

## 一、结论

平台自带的「连接容器」面板是**裸 socket 通道**（发送二进制/十六进制/HTTP 原始字节，不执行题目 HTML），
给 nc 类题目用的。六道 Web 题需要的是浏览器入口，现已补上：

| 题目 | 浏览器做题入口 |
|---|---|
| HC-01 人机验证 | http://PLATFORM_HOST:8081/entry/HC-01/ |
| SUDOKU 异形数独拼图 | http://PLATFORM_HOST:8081/entry/SUDOKU/ |
| SNAKE 原型链贪吃蛇 | http://PLATFORM_HOST:8081/entry/SNAKE/ |
| MISSING 消失的方块 | http://PLATFORM_HOST:8081/entry/MISSING/ |
| MORSE 摩斯与 MD5 | http://PLATFORM_HOST:8081/entry/MORSE/ |
| SRCFLAG 查看源码 | http://PLATFORM_HOST:8081/entry/SRCFLAG/ （自动跳 /SACC） |

平台本体：http://PLATFORM_HOST:8081/

## 二、使用方式

1. 先在平台登录（同一浏览器，cookie 名 tq_session）。
2. 直接点上面的链接。
3. 没有容器时网关会**自动为你启动本题容器**，页面每 2 秒自刷新，10–40 秒后进入题目。
4. 若当前占用着别的题容器，网关会**自动销毁旧的、启动这道题**（平台限制：一个队伍同时只能开一个容器）。

## 三、实现

- 新增容器 `tq-entry-gateway`（镜像 tq-entry-gateway:6，源码 F:\Desktop\test\_work\entry\gateway.mjs）
  - 网络：sacc-service-net（调平台 API）+ tracequest-runtime（直连题目容器）
  - 逻辑：解 tq_session → 调 `GET /api/v1/events/{event}/challenges/{code}/runtime/instances/me`
    → READY 则反代到 containerIp:containerPort；STOPPED/无实例则 POST 自动启动；409 则先销毁其它题容器再重试
  - 反代时：剥前缀、Host 改为容器地址、**Origin/Referer 折算到容器自身地址**（容器普遍做同源校验）
  - 响应重写：文本响应里 `"/xxx"` → `"/entry/<CODE>/xxx"`，HTML 注入 `<base href="/entry/<CODE>/">`
  - Set-Cookie 的 Path 改写为 `/entry/<CODE>/`，避免污染平台会话
- 前端 nginx（bind mount 文件 `/home/sacc/tracequest-frontend/releases/20261102T204207-d11b22cd0330/nginx.conf`）
  - 新增 upstream `tq_entry_gateway` 与 `location ^~ /entry/`
  - 备份：同目录 `nginx.conf.bak-20261104112711`

## 四、验证记录

- 公网 `GET /entry/HC-01/` → 200 / 45046B / 注入 base；5 步通关 → `POST /api/claim` 200 拿到本队 flag
  → 平台 `POST /api/v1/challenges/HC-01/submissions` → 200 `result: correct`
- 六题页面：SUDOKU 60295B / SNAKE 4696B / MISSING 1574B / MORSE 5116B / SRCFLAG(/SACC) 200 含 flag / HC-01 45046B
- 同源校验：SNAKE `POST /api/level/1/score` → 200（Origin 重写前是 403「只接受同源请求」）
- 自动起容器：清空后打开 /entry/HC-01/ → t+0s 启动中 → t+4s 题目页
- 自动换容器：MORSE 占用中打开 /entry/HC-01/ → 旧容器销毁、HC-01 就绪

## 六、前端「如何做题？」引导（2026-11-04 晚追加）

参赛者不知道 Web 题该点哪里（平台只有「连接容器」面板），因此把引导做进了平台前端。

### 效果
- 平台任意页面右下角常驻「● 如何做题？」悬浮按钮（对所有角色可见，含未登录访客）。
- 点开是引导面板：
  1. 一句话说明「连接容器」是裸 socket 通道、不渲染网页；
  2. 若当前 URL 命中某道容器题（如 ?view=detail&code=HC-01），顶部绿色区块显示「你正在看：人机验证 HC-01」+「开始做这道题 →」；
  3. 容器题列表（实时取自 GET /api/v1/challenges 里 containerEnabled=true 的题目，按分值排序），每行一个「进入题目」按钮 → /entry/<code>/；
  4. 「为什么不能用连接容器面板」说明 + 三条小提示（一队一容器、启动等 10–40 秒、拿到 flag 回平台提交）。
- 直达：http://PLATFORM_HOST:8081/?tqguide=1 会默认展开面板（截图/演示用）。

### 实现（两段）
1. 脚本：F:\Desktop\test\_work\entry\guide.js（纯原生 JS，无依赖，7.6KB），由入口网关容器在 GET /tq-guide.js 提供（网关镜像 tq-entry-gateway:9，源码 entry/gateway.mjs 的 /tq-guide.js 分支）。
2. 注入：前端 nginx 配置（宿主 bind mount 文件 /home/sacc/tracequest-frontend/releases/20261102T204207-d11b22cd0330/nginx.conf）
   - 新增 location = /tq-guide.js { proxy_pass http://tq_entry_gateway; }
   - location / 内新增 sub_filter 把 <script src="/tq-guide.js" defer></script> 注入到 index.html 的 </body> 前；sub_filter_once on;
   - 改完 docker exec tracequest-frontend nginx -t 通过后 docker restart tracequest-frontend。

### 改文案 / 换题目
只改 guide.js（题目列表是运行时拉接口，题目增减不用改代码），然后重建网关镜像并重启容器：
